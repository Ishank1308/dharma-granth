# Dharma Granth: Data Sources, Build Guards & Scripture Pipelines (Imported from Claude Memory)

## 1. Runtime Scripture Data Sources (`scripture-data-sources` & `dharma-granth-next-stale-build`)
- **Runtime source of truth:** Runtime verse text is loaded from `public/data/scriptures-full/<id>.json` (via `data/scriptures/lazy.ts` using `readFileSync` at build/server time, and per-chapter shards `{id}/ch-N.json` generated by `cmd /c npm run shard:scriptures`).
- **Dead runtime copies:** `data/scriptures/*.ts` ("curated" TS modules) are **NOT** imported at runtime — only by offline scripts. Never use dynamic `require(\`@/data/scriptures/${id}\`)` in app/server code: webpack will bundle all 67 `.ts` modules (~115 MB `mahabharata.ts`) into ~827 MB server chunks and crash Node with `ERR_STRING_TOO_LONG`.
- **Bhagavad Gita numbering:** 701 verses total; Chapter 13 has 35 verses (Arjuna's opening question = `13.1`, whose source Hindi is intentionally empty). `scripts/check-data.ts` guards against Gita count/duplicate drift and labelled/credit-only Hindi.
- When fixing scripture data: update `public/data/scriptures-full/<id>.json`, run `cmd /c npm run shard:scriptures`, regenerate metadata (`cmd /c npm run generate:metadata-json`), and match verses by normalized content rather than array index when merging.

## 2. Cloudflare Pages Export & Size Limits (`deploy-size-limits`)
- **Deployment limits:** Cloudflare Pages enforces **20,000 files** and **25 MiB per file** per deployment.
- **Split origins in CI:** Verse share images (`public/og/verse/`, `NEXT_PUBLIC_SHARE_IMAGE_ORIGIN`) and published commentary (`public/data/hi-commentary/<id>/<chapter>-<unit>.json`, `NEXT_PUBLIC_COMMENTARY_ORIGIN`) deploy as separate Cloudflare Pages branch deployments (`share` and `commentary`), keeping the main site deployment under 20,000 files (`scripts/prune-export.mjs`).
- **Chapter inlining & part splitting:** Chapter pages inline lightweight `VerseText` HTML at build time (`FullChapterVerses` upgrades batches to rich `VerseCard`s progressively — never server-render full `VerseCard` HTML for all 4,200+ chapters). Chapters exceeding byte/verse thresholds are split into parts (`lib/chapter-parts.ts`, `/scripture/<id>/chapter/<n>/part/<p>/`).
- **Satori share images:** Verse OG share images (`scripts/generate-og-images.ts`) use IAST rather than Devanagari because Satori cannot shape Devanagari conjunct ligatures cleanly.

## 3. Upanishad Filler-Verse Validation (`filler-verse-contamination`)
- Canonical Upanishad totals in `data/scripture-meta.ts` (e.g., Isha 18, Kena 35, Katha 119, Prashna 67, Mundaka 64, Mandukya 12) are authoritative. Beware `mergeCuratedChapters` in seed scripts, which previously appended template filler verses into seeded JSONs.
- Validate Upanishads against `sanskritdocuments` sources with `cmd /c npx tsx scripts/_validate-upanishads.ts` and rebuild keeping annotations via `cmd /c npx tsx scripts/rebuild-upanishads.ts <id> [--write]`. Note: `shandilya.itx` is the Upanishad, not the Narada/Shandilya Bhakti Sutras.

## 4. Ashtavakra Gita Pipeline (`ashtavakra-pipeline`)
- **Source PDF:** `C:\Users\ishan\Downloads\Documents\Ashtavakra-Gita-Sanskrit-Hindi.pdf` (405-page CCITT scan, no text layer; printed page = PDF page − 7; 20 prakaranas). Render pages to PNG via `@napi-rs/canvas` + `pdfjs-dist` in scratchpad and inspect visually (crop/zoom doubtful ligatures; flag print discrepancies as `review-required` rather than guessing).
- **Build scripts:** Author `data/ashtavakra/chN-src-*.mjs` + `chN-chapter.json`, then run `cmd /c node scripts/ashtavakra-compose.mjs N` and `cmd /c node scripts/ashtavakra-build.mjs N` (writes `chapter-N.json` and `docs/ashtavakra/chapter-N.md` with required safety metadata).
- **Editorial rule:** Write original summaries of the commentary (never copy verbatim), add support/ethics notes on sensitive body/death verses, and omit any sectarian, caste, or misogynistic polemic from the source commentary. Audio is omitted site-wide.

## 5. Durga Saptashati Pargiter Pipeline (`durga-pargiter-pipeline`)
- English translations live in `scripts/cache/durgasaptashati-translations.json` (hand-aligned from Pargiter's 1904 translation, cantos 81–93 → chapters 1–13; Chapter 5 uses merged litany keys `5.77` for 14–76 and `5.81` for 78–80).
- Never run `seed:durgasaptashati-translations --force` without immediately running `scripts/restore-durga-curated.ts` (which restores curated fields by normalized-Sanskrit match) followed by `cmd /c npm run shard:scriptures`.
