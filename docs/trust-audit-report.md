do NOT market AI. Technology is positioned as an assisting tool, scripture as the source, wisdom as the outcome.

## Decisions on prior gaps

1. `SourcesAndInterpretation` stays chapter-only (mounted only in `chapter-view.tsx:547`). Verse pages
   get the new compact `SourceStudyNotes` block instead of extending the layer-sources card, so the
   Sources card keeps its single job as the provenance record.
2. The new block is a presentational, client-safe component rendered in verse `page.tsx` children
   (server HTML), which also makes it reusable inside client readers without server imports.
3. No `lib/seo.ts` exists and none was created; SEO is split across `lib/meta-text.ts`, `lib/og.ts`,
   `lib/jsonld.ts`, `lib/jsonld-graph.ts`, `lib/verse-paths.ts`. Repositioning was done at the call
   sites (layout defaults, verse metadata/JSON-LD).
4. No explicit Verse → Scripture → Commentator → Acharya → Saint chain object existed; chains were
   emergent (verse lens → topic scripture refs → `lineageIds` masters + sources-registry commentary
   authors). `lib/lineage-chain.ts` now builds that chain from recorded data only. No master detail
   pages or lineage sitemap entries were added (out of scope for this overhaul).
